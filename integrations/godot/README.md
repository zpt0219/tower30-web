# Godot共享TS核心 · 原生资源闭环

这是独立的Linux x86_64 Godot 4.6.2 .NET样机，不是原Godot工程的替换版。原工程保持只读。网页工程联调见 `docs/PROJECT-HANDOFF-STATUS.md`，原生资源流程见 `docs/GODOT-FLOW-STATUS.md`；首次接入记录保留在 `docs/GODOT-BRIDGE-STATUS.md`。

## 在仓库中运行

要求Node >=22.12、npm、.NET 9 SDK、GCC、curl、tar以及Godot **4.6.2 .NET**版。

```sh
npm ci
# 非本机默认安装位置时指定 .NET 版引擎：
export GODOT=/absolute/path/to/Godot_v4.6.2-stable_mono_linux.x86_64
npm run godot
```

`npm run godot`构建同一份TS核心、校验并编译QuickJS适配库、构建C#，导入原生资源后启动本目录。没有Node游戏服务，也不读取兄弟工程。单独构建为 `npm run build:godot`，可重复的跨宿主检查为 `npm run test:godot`。

默认从240金币与原始两位人类/初始装备进入战前整备，购买装备需要明确确认，再点击穿戴。可以培养、升阶、退还药水、使用草药/复活羽与付费旅馆恢复；所有操作只向同一TS核心提交命令。装备页同时显示最终属性、当前装备加成和技能描述。

依次点击“战前布阵 → 开始交战 → 查看战报 → 确认战果 · 下一层”。布阵最多5首发，战中可手动大招与补人。失败/撤回可恢复该层检查点重试；确认胜利发放一次奖励并保留生命/能量，30层后进入完成页。Boss后商店阶段与旅馆价格直接读取核心。

战中使用左右侧面素材，移动时播放行走帧，站定时使用侧面站姿。胜利后只有存活友军切正面踏步；这段动画不推进战斗tick。网页采用同样切片规范。两侧图不是正面贴图翻转。

“保存进度/载入进度”使用独立原生文件槽；当前进度每60个逻辑tick与重要命令后自动保存。默认位于Godot自定义用户目录 `tower30-web-shared-core` 下的 `tower30-ts-session.json`，手动槽后缀 `.manual`，替换时保留 `.bak`。恢复战斗默认暂停，未确认战报保留阶段。不能读取原Godot存档。主档读取失败时保留原件并停止自动写盘；用户确认新试跑后另存损坏原件再重新开始。长记录恢复需要同步重放，加载期间可能停顿，尚未做异步加载页。

“调试场景”创建百万生命、双方10存活单位的独立Play测试，关闭自动大招；仅临时保存测试档，不写正式进度。点击“返回正式进度”恢复进入前状态。

## 网页编辑 → Godot Play

1. 网页工作台修改角色、关卡、技能、效果和策略，设置种子，点击“导出Godot试跑”。普通“导出工程”文件也兼容；“导出配表”没有测试设置，不能代替工程。
2. Godot点击“工程 / Play → 选择工程 JSON”。文件先通过同一TS校验，预览关卡、种子、阵容、策略、配置标识和试跑标识；尚不替换当前会话。
3. 点击固定在底部的“▶ Play 第N关”启动。配置与设置被冻结，执行相同策略控制器；无正式金币消耗或奖励。
4. “同配置同种子重开”始终重开当前冻结测试。重新导入B只改变待启动预览；要运行B必须明确点击Play。
5. 保存进度将工程测试写到正式槽旁的独立 `.project.manual` 槽，压力测试仍只临时保存。“恢复上次项目测试”可重放该槽。返回正式进度恢复进入测试前状态。
6. 在工程页“导出测试记录”，选择JSON保存位置。网页工作台“导入测试记录”可暂停回放并继续；不会将记录中的配置改写为当前草稿。网页测试战斗也能直接导出当前记录，无需先撤回。

文件限2MB。项目使用既有 `tower30-editor-project` / schemaVersion 1，包含原始source和setup；共享 `src/core/project.ts`校验，不在C#实现第二套校验或战斗。配置/试跑标识为FNV指纹，用于核对配置与设置，不是安全签名。恢复工程测试额外核对完整规范化配置和完整设置；失败不替换当前会话。

也可预览指定文件：`npm run godot -- -- --project=/absolute/path/to/project.json`。这仍需在界面点击Play；不创建文件监视器或自动热换配置。

## 下载的工程包

下载包保留本目录结构、生成的JS/配表/少量精灵图及Linux本地库。解压后用Godot 4.6.2 .NET打开 `project.godot`，构建C#并运行；或设置 `GODOT` 后执行包中的 `RUN.sh`。包里没有Godot编辑器或.NET SDK，也不是APK或已导出的独立游戏。

## 桥接边界

`src/bridge/session.ts`提供同步JSON协议1：`create`、`restore`、`command`、`advance`、`snapshot`、`frame`、`events`、`save`、`dispose`。请求通过Zod校验，响应为 `{version:1,ok:true,value}` 或 `{version:1,ok:false,error}`。命令的业务拒绝保留在 `value.ok/message` 中。

- `create`接收完整配置和可选种子/Play设置，替换会话前完成校验。
- `advance`只接收整数tick，使用共享策略控制器推进；返回战场快照和事件。
- `restore`正式档需传配置，Play档自带配置；旧20Hz档沿用现有核心迁移规则升级到60Hz。
- `save`返回核心序列化字符串；不在C#重建战斗状态。
- `events`和frame里的events与核心一致，是最近64条事件的只读窗口，**不是清空式事件队列**。消费者按单调event.id去重；批量推进可能越过窗口，不能宣称收到每次命中事件。
- 每个会话只在所属线程调用；C#对象、Node、浏览器和Godot对象都不穿过协议。

`native/bridge.c`仅创建QuickJS上下文、调用JSON函数、转交错误并释放内存；`host/QuickJsSession.cs`仅封装P/Invoke和JSON。这两层没有伤害、价格、随机或胜负计算。

## 当前限制

完整30层正常资源记录已在Godot进程内重算对照。原生界面已覆盖最小资源闭环；当前未接原Godot角色场景、动画树、音效、完整技能表现、完整卖出/卸装管理和自动经济策略。

当前仅构建Linux x86_64 `.so`；Android/Windows/macOS的本地库、Godot导出打包、真机性能与触控体验尚未验证。横屏检查为1000×450本机窗口，不能称为手机实测。
