# v0.8 · 多关批量测试

v0.7效果参数版本已提交为`7b7ce47`，可作为稳定基线。本次在“工作台 → 批量对比”中加入多选关卡、逐关统计、失败样本筛选、分页与整组报告。战斗实现、自动策略、正式进度和独立Play记录规则保持同一核心。

## 使用

1. 展开“选择测试关卡”，勾选1—30关；也可选“当前关卡”“10 / 20 / 30 Boss”“全部关卡”。“当前关卡”跟随测试设置，其余选择固定保存。至少选1关。
2. 设置**每关、每份配置**运行1—100个种子。计划场次为关卡数×种子数×A/B。最大30关×100种子，即3000对、6000场。
3. 保存A并修改草稿B，统一使用阵容、等级、阶数、初始生命/能量、武器、技能执行模式与自动策略。所有选关先完成校验和首发入场检查；完整模式任一选关不支持即整组阻止，数值模式按关记录停用警告。
4. 按一个种子依次跑所有选关，再换下一个种子。A/B每对同种子，每关使用同样种子序列，超过4294967295回到1。
5. 每场创建新的核心实例。生命、能量、补人票和随机状态均从测试设置重新开始；不会跨关携带损耗、掉落或资源，不代表正常资源连续通关。

选关与有效次数/策略偏好和A配置一并保存，刷新后恢复。当前结果仍存于本页内存，刷新前请导出报告。运行后关卡、配置与设置冻结，可继续编辑草稿；旧结果会提示重新运行，历史战果不重新计算。

## 统计与复现

- **逐关汇总**：每关实际完成数/计划数、A/B胜率、平均耗时、补人和能量消耗。点关卡进入其详细资源统计。
- **范围与筛选**：可选全部关卡或单关；样本列表支持全部、A未胜、B未胜、任一方未胜。未胜包括失败与超时。筛选只改变列表，指标仍统计该范围的全部已完成样本。
- **每页20对**：大量样本分页显示，后台进度合并刷新。过滤、翻页后保留原始样本索引。
- **查看战果 / 导出记录 / 手动Play A或B**：使用该行真正的关卡、种子和冻结配置。即使当前Play关卡已切换、草稿又被修改，也不会把第20关样本错误地打开成当前第7关。
- **取消**：保留已记录的完整配对，不将正在运行的一对计入。逐关按自己的实际样本数作分母；未运行关卡显示“—”。同种子轮流逐关运行使取消时各关已完成数最多相差1。

整组导出仍为`tower30-comparison`，多关报告升为`schemaVersion:2`，包含显式`floors`、每对的`floor`、逐关停用警告、配置、设置、策略版本、全部命令和汇总`byFloor`。`setup.floor`保留单关Play设置，不能代替每行的关卡。核心`simulatePair`、`simulationJob`与`trialSave`理解v2，也继续支持旧v1单关报告；旧版代码应使用其对应报告格式。

逐场导出仍为独立Play v5记录，现有核心通过命令重放查看终局，不能通过写入统计结果来伪造胜负。正式存档格式及原始配表指纹不变。
