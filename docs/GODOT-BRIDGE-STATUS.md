# v0.11 · Godot运行同一TS逻辑的接入验证

本次新增独立工程 `integrations/godot/`。原Godot工程保持只读；新样机没有复制原C#玩法，也不依赖兄弟目录。网页版M0—M4已有功能保持不变。本次完成的是共享核心接入验证，不是完整Godot版本交付。

## 已经跑通

`src/core`和纯JSON适配层 `src/bridge/session.ts`被打成IIFE `tower30-core.js`，包含锁定版本Zod。Godot 4.6.2 .NET通过薄C#/C适配层调用QuickJS 2026-06-04，由这个bundle计算全部玩法。

运行时只交换命令、整数tick、快照、事件与核心存档字符串。C#不计算伤害、金币、价格、随机或胜负。正式档和Play档复用网页存档模型；当前样机的保存按钮只保存在内存，尚未接磁盘存档菜单。

Godot `_PhysicsProcess`每次推进1个 `1/60秒`逻辑步；`_Process`使用独立视觉时间，插值相邻状态并绘制现有本地精灵、生命/能量、护盾和弹道。画面限制到30FPS时逻辑仍保持60Hz。两者仍在同一主线程，未宣称多线程实时保证。普通运行遇到超过0.5秒长帧会明确暂停。

原生界面包含正常预算第1场、重开、暂停、继续、单步、手动大招、内存保存/恢复和独立20单位调试场景。压力场景增加测试生命值并关闭自动大招，明确标注调试且不计正常通关。

## 实际检查

- `npm run typecheck`：包含无宿主API的核心与JSON边界，严格检查通过。
- `npm run test -- --run --maxWorkers=4`：19个文件、86项通过。新增3项桥接检查覆盖与直接核心等结果、非法请求不替换会话、会话隔离及销毁；其余60Hz与既有规则检查保留。
- `npm run build`：网页静态构建通过；本次未改网页UI，未重复完整浏览器回归。v0.10的50个不同浏览器流程记录见对应交付文档。
- Godot C#构建：0警告、0错误。QuickJS第三方源码和Zod构建注释有工具链警告，不影响完成构建。
- `npm run test:godot`：构建、导入、V8记录生成、Godot进程内重算与比较的整条命令实际执行通过。

跨宿主检查共 **820条请求、39个检查点、482878个数值比较**。使用实际正常资源60Hz操作记录，通过商店购买、装备、培养、付费住宿、布阵、大招、补人和结算命令在Godot进程中重算30层，最终 **35487 tick、591.45秒、610金币**。还检查正常战中存档续跑、Play战中续跑、20名存活单位、非法请求保留原状态及会话释放。

整数（包括生命、伤害、金币、种子、tick和命令结果中的整数）要求精确相同；浮点使用绝对容差1e-9。观测到的最大绝对差异为 **1.7763568394002505e-15**，因此不声称两个JS运行时逐位相同。序列化存档先解析再比较字段，避免把不同等价浮点打印文本当成玩法差异。

原生按钮检查在桌面1280×720、横屏1000×450各通过11项，包括暂停保持tick、单步只走1步、正式/Play战中恢复、重开和恢复结束前的档后再次完成战斗。两者均由真实Godot物理更新走到第1层555 tick胜利；没有预设结果。检查通过Godot Button pressed信号执行，不是系统鼠标/触摸自动化。实际查看两个尺寸的战果、20单位截图；横屏采用expand填满20:9画面。

20单位性能在本机Linux、Xvfb、Mesa llvmpipe软件渲染下测量。先预热60个实际物理tick，再测360 tick，包含同步逻辑、共享策略、JSON序列化、P/Invoke和JSON解析；不含绘制本身：

| 条件 | 实测逻辑 | 画面FPS | 平均每步 | P95 | 最大每步 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1280×720，画面上限60FPS | 59.956Hz | 50 | 5.171ms | 8.185ms | 13.425ms |
| 1000×450，画面上限30FPS | 60.065Hz | 30 | 7.470ms | 11.733ms | 14.728ms |

两组均为10名友军和10名敌军实际存活。结果只证明本机样机稳定阶段；启动、资源导入和JIT不计入此表。没有Android导出或物理手机测试，不能据此保证手机60Hz。画面较低时仍实际推进约60步/秒，验证了逻辑频率不跟着画面降到30。

两份原始JSON的SHA-256继续与 `data/SOURCES.json`一致。

## 距离完整Godot体验仍缺的功能

1. 把原Godot服务和管理页面改为命令/快照适配：伙伴、装备、背包、商店、培养、旅馆、关卡、战报、结算与下一层。现在是独立样机，原C#服务未替换。
2. 用核心状态和事件驱动原生角色场景、动画树、完整技能/受击/状态特效、音效。当前只做了基础2D显示，尚无完整事件表现消费层。
3. 原生持久化存档、导入导出、项目配置加载与网页编辑结果的交接。JSON协议已经有入口，完整操作流程尚未接入。
4. Android等目标平台的QuickJS本地库、资源导出/动态库装载与Godot打包；真机CPU/内存/触控/后台恢复验证。本次只支持Linux x86_64编辑器运行。

建议下一步先接 **Godot正式资源“战前准备 → 战斗 → 战报结算 → 下一层”** 的最小闭环，再补齐其余管理菜单；不用继续迁移一份玩法。
