# v0.9 · 自动战斗策略编辑器

v0.8多关批测已提交为`a006c7c`。本轮推进M4调参工具：在工作台新增“战斗策略”，用同一份纯TS命令控制器驱动策略Play、单步和A/B批测。战斗伤害、治疗、目标、能量、票数和经济仍由原核心执行。本轮不加入正常流程自动托管、购买/培养/旅馆决策或任意脚本编排。

## 网页用法

1. 在“测试设置”选好阵容与初始状态，进入“战斗策略”。默认Play继续手动释放大招与补人；勾选“Play自动执行策略”后，按Play开始新测试。正式试跑仍为手动大招。
2. **治疗大招**可选低于阈值、满能立即释放、不自动释放。阈值为0—100%，严格低于才触发；0%表示不触发。按配置中的治疗伤害类型识别技能，包括把治疗类自动技能配置为大招的情况。只判断存活在场队友；实际是否有可治疗目标、是否可出招仍由核心检查。
3. **打断大招**可选等待敌方吟唱、满能立即释放、禁用。此条件用于`interrupt`截风。其它输出或增益大招满能后尝试释放。“允许自动大招”关闭后不自动释放任何我方大招。
4. **大招优先级**使用上移/下移调整，控制同tick的尝试顺序。所有角色仍须满足1000能量、入场和状态限制，顺序靠前不保证能成功出招。条件使用该tick决策前的快照，同tick多个治疗者可能同时出招。
5. **补人顺序**调整候补尝试顺序，已首发、已上场或倒下成员不会重复加入；每tick最多成功补1名，不能越过票数和10名在场上限。“允许自动补人”可以关闭。更改补人顺序不改变首发。
6. 策略、Play自动开关与测试草稿一起自动保存，也包含在工程JSON中。配表JSON与“导出A配置”只包含玩法配置，策略使用工程或整组报告备份。越界阈值阻止Play/批测，刷新仍保留该草稿供修复；恢复默认策略保留Play自动开关。
7. 阵容中移除或替换成员后清理其优先级引用，新成员按原阵容顺序补在后面。导入策略拒绝重复成员、阵容外成员、非法开关、阈值和未知字段。

## 比较两套策略

“保存A”同时保存配表与当前策略。之后只改B策略，即可在**相同属性、同阵容、同初始资源、同关卡和同种子**下比较决策；也仍能同时比较配表改动。未曾保存策略的旧A配置沿用默认策略。

批测始终自动执行各自策略，不取决于“Play自动执行策略”开关。批测顶部“不使用我方大招”和补人总开关是双方共同限制，优先于各自策略。运行前验证全部选关、两份配置及其策略，开始后冻结。改策略会提示旧结果保留，请重新运行。

报告显示配表指纹；配表指纹相同不代表策略相同。可以展开“查看本次A/B策略快照”查看治疗、打断和两种优先级。逐关结果、样本筛选、分页与取消保持原口径，各关独立开局。

每行提供两种重新开局方式：

- **策略Play A/B**：使用该行原关卡、种子、冻结配置及批测共同限制生效后的策略，自动执行；手动干预后轨迹可发生变化。
- **手动Play A/B**：使用同样配置与策略参数，关闭自动执行，由玩家释放大招/补人。

“查看战果”和逐场记录仍以实际命令重放终局。修改当前草稿不会改写样本、策略或已有Play会话。

## 保存与兼容

- 新策略报告为`tower30-comparison` **schemaVersion 3**、`tower30-policy-v2`，在原多关格式上为A/B分别增加`strategy`快照。`setup`仍包含当前Play草稿，逐场实际策略以报告对应变体加共同限制为准，不能用B的当前草稿代替A策略。
- 带策略或自动开关的独立测试记录使用`tower30-ts-workbench-v6`。不带这些字段的旧测试继续使用v5；v4/v5记录仍可恢复，旧工程无需补写策略。
- 旧v1/v2报告保留原v1控制器口径：治疗阈值65%、原四类治疗大招和默认顺序。原始JSON与配表指纹不变，正式存档格式不变。
- 核心`advance()`只推进玩法，重放按已存命令执行。策略调度由`advancePlaytest()`逐tick调用，恢复记录不会再次自动生成过去的命令。正常Play、单步、倍速和批测使用同一`applyStrategy()`；后台暂停仍适用。
- 本轮使用JS自带WeakMap缓存不可变配置的治疗分类，不保存决策状态、不改变随机序列或跨会话状态。控制器无DOM、Node、Vite或Godot依赖。
