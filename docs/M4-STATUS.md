# v0.6 · M4调参工具首版

在v0.5完整30层基础上，工作台新增单关批量模拟与A/B配置对比；补齐战斗事件筛选。既有暂停、单tick、倍速、固定种子、配置冻结和独立Play继续共用同一个纯TS核心。正式战斗规则与存档版本未变。

## 使用

1. 工作台 → **批量对比**。默认A是原始配表，也可点击“将当前草稿保存为A”；A单独存入浏览器，刷新后保留，可导出JSON备份。
2. 在角色、关卡、技能页调整草稿B。测试设置统一应用到A/B，包括阵容顺序、关卡、等级、阶数、初始生命/能量、初始武器及完整/数值模式。
3. 每份配置运行1—100次。第一个种子使用测试设置的种子，每次+1，超过4294967295回到1。A与B每对使用相同种子，不共享一场战斗的状态。
4. 选择择机大招或不用我方大招，决定是否按阵容顺序补人，点击“运行A / B配对模拟”。后台Worker运行，可继续编辑、查看进度或取消。只有完整结束的配对样本计入统计；取消丢弃正在运行的一对。
5. 查看逐个种子的A/B结果；可查看该场真实终局、导出复现记录，或用B的冻结配置和该种子重新手动Play。导出对比报告包含两份配置、设置、策略版本、全部命令、每场结果及汇总。结果暂不跨刷新保存，请刷新前导出；A与草稿分别持久保存。

开始后配置与设置冻结，修改A、草稿或测试设置会提示旧结果需要重新运行。历史结果不随当前草稿重新计算。查看测试终局通过`TowerEngine.restorePlaytest`重放真实操作记录，不把统计数字塞回战斗状态。

## 策略及统计口径

策略版本为`tower30-policy-v1`：人类优先，其余按阵容顺序补足5首发；每tick尝试满能大招。新芽复苏、林息、圣祈、森林庇护等待存活队友生命低于65%，截风等待敌方吟唱，其余立即尝试。自动补人按阵容顺序，每tick最多1名。全部释放、目标可用性、票数、入场、胜负由现有核心处理；敌方仍按原规则行动。每场最多6000tick（300秒），超时单列，不记成胜利。

统计包括胜场/失败/超时、全样本平均耗时、胜场平均耗时、平均倒下和补人、战后/初始生命、实际大招耗能与三类有效回能、有效伤害/治疗/护盾吸收，以及仅A胜、仅B胜、都胜、都未胜的配对计数。空样本显示“—”，不伪造0%胜率。生命包含未出场候补，治疗后可以超过开战时的低生命比例。

这里是**单关独立战斗测试**，不会购买、培养、住宿或发放掉落；不是自动跑完30层经济策略的工具。统计是指定阵容、设置与自动策略下的样本描述，不等于玩家胜率，也没有做显著性结论。完整30层正式资源闭环的证明仍见[完整30层记录](FULL30-STATUS.md)。

## 战斗事件

战场调试区可以按命中、治疗、护盾、大招吟唱、动作打断、控制、弹道发射筛选，并按角色或目标的ID/名称搜索。显示核心最近64条事件；筛选只改变显示，不推进tick、不提交战斗命令。短屏展开面板时覆盖战场下部，保留暂停/继续与返回编辑操作区。暂停后可单tick查看实际命中与控制时点。

- `npm run typecheck`：主程序与无宿主API核心严格检查通过。
- `npm run test -- --run`：57项核心测试通过。新增同配置同种子一致、冻结输入、复现记录精确重放、正式存档隔离、弱配置失败/强配置获胜、空样本、种子边界、严格技能校验、真实补人和300秒超时。

- 静态HTTP上的`npm run test:e2e`：34项，桌面1280×720与横屏1000×450各17项。新增保存A/编辑B、实际Worker模拟、胜负差异、取消、非法次数、导出报告和复现记录、查看冻结终局、手动Play、刷新保留A、草稿变更提示、事件筛选和正式资源保持。横屏使用实际触控滑动验证统计区域滚动。
- 实际查看两种视口的对比、资源、操作区和事件筛选截图；横屏为Chromium模拟，未宣称真机验收。
- 原始两份JSON继续与`data/SOURCES.json`的SHA-256一致。没有更改Godot工程，也不需要Godot/.NET运行本工具。

额外实际运行30组第30层配对（60场）：Lv.10/怪兽3阶、9人阵容、满生命零能量、初始武器、择机大招/自动补人、种子2463534242起。A为原始配置，B仅将主角基础攻击乘1.1。A胜28/30，B胜23/30；仅A胜7、仅B胜2、都胜21。结果会随动作节奏与随机消费路径变化，这30个种子不构成平衡结论；未据此修改原始配表。完整条件与操作保存在`boss30-30pairs.json`。
