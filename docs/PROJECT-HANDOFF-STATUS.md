# v0.13 · 网页编辑工程与Godot Play往返

本次完成“网页调参 → 导出工程 → Godot预览 → Play → 导出测试记录 → 网页暂停回放/继续”。继续使用相同TS核心、配表适配、策略、固定60Hz和命令存档，原Godot工程保持只读。

## 使用

1. 网页工作台修改角色、关卡、动作/效果、阵容、种子与策略。点击 **导出Godot试跑**。策略页也有该按钮；配置或设置无效时不能导出可运行工程。普通“导出工程”也兼容，单独“导出配表”缺少setup，不能当工程使用。
2. 运行 `npm run godot`。点击 **工程 / Play → 选择工程 JSON**，预览待启动的关卡、种子、阵容、策略与标识。
3. 点击底部固定的 **▶ Play 第N关**。建立独立测试，不扣正式资源、不发正式奖励。
4. **同配置同种子重开**始终使用当前运行的冻结A；重新导入B只改变待启动预览，必须再点击Play才切到B。没有文件监视器或后台热换参数。
5. 原生保存/读取项目测试使用独立 `.project.manual` 槽。返回正式进度后，仍可在工程页“恢复上次项目测试”。压力场景继续只保存临时测试，不混进项目或正式槽。
6. 原生工程页 **导出测试记录**，再从网页工作台 **导入测试记录**。以记录里的配置、策略、种子和命令恢复，默认暂停；可单步或继续，不将记录配置覆盖进当前草稿。网页独立战斗新增直接导出记录，无需先撤回。

命令行预览：`npm run godot -- -- --project=/absolute/path/to/project.json`。同样先预览，再手动点击Play。

## 数据和边界

工程沿用 `tower30-editor-project` / schemaVersion 1，包含完整原始source与setup；保留未参与运行的原始源字段。新增 `src/core/project.ts`作为宿主无关的统一schema、校验、冻结和试跑工厂。文件上限2MB，按UTF-8和标准导出文本检查。没有额外服务器或C#玩法实现。

桥接增加 `inspect-project`、`play-project`、`restore-project`和只读 `config`。预览不修改当前引擎；Play在候选引擎完成校验、begin与start后才替换会话，入场失败不损失旧测试。恢复冻结测试除了检查配置指纹，还比较完整规范化配置和完整setup；错误记录不替换当前状态。

配置标识由规范化配置计算，试跑标识包含配置标识与完整setup（种子、策略等）。两者为FNV核对指纹，不是安全签名。文件里的JSON是数据，不执行外部脚本，不导入用户提供的图片路径；使用仓库已有42张角色图。

Godot工程页同时保留待启动B与当前冻结A的信息。文件选择、Play、重开、记录导出与返回操作互相独立；打开工程页暂停当前战斗。当前测试存在独立槽，不向正式自动档/手动档写入工程测试。
